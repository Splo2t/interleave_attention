# Interleave Attention Evaluation

Minimal artifact code for reviewing the CIKM 2026 interleave-attention
experiments. This repository keeps only:

- evaluation entrypoints,
- benchmark packages,
- the sanitized Stage-2 training reference script,
- lightweight documentation for expected inputs.

The trained model checkpoints are distributed separately, for example through
Google Drive. This repository does not contain model weights, checkpoint
conversion utilities, dashboards, Excel exporters, or local sweep shell scripts.

## Repository Layout

- `eval_paper_benchmarks.py`: single-model evaluator for the main benchmarks and Korean reranking.
- `eval_variant_hf_krong.py`: evaluator for KoBEST surface-form stress JSONL data.
- `run_eval_checkpoint_sweep.py`: convenience runner for evaluating one downloaded model on multiple tasks.
- `krong_eval/`: main benchmark package.
- `krong_eval_variants/`: KoBEST variant/stress benchmark package.
- `training/stage2_train.py`: sanitized training reference code.
- `docs/`: artifact notes and reranking input schema.

## Setup

Use Python 3.10+.

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

Optional training-code inspection or reruns use:

```bash
pip install -r requirements-training.txt
```

The training script also expects the original training-only modules `kormo`,
`krong_tokenizer`, and `llama_interleave` on `PYTHONPATH`. Evaluation does not
require those modules.

## Checkpoints

Model weights are not committed to git. Download the artifact checkpoints and
place them under an ignored local directory such as:

```text
checkpoints/
  stage2_interleave_18k/
  matched_decoder_only_cpt_control_18k/
  vanilla_cpt_19k/
```

See `docs/artifacts/model_checkpoints.md` for the paper checkpoint mapping.

## Main Benchmark Evaluation

Single benchmark smoke test:

```bash
python eval_paper_benchmarks.py \
  --ckpt_path checkpoints/stage2_interleave_18k \
  --model_arch krong \
  --task mmlu \
  --subjects abstract_algebra \
  --cache_root ./hf_cache \
  --limit 10 \
  --out_json outputs/smoke_mmlu.json
```

Run the paper main task set for one downloaded model:

```bash
python run_eval_checkpoint_sweep.py \
  --single-ckpt-path checkpoints/stage2_interleave_18k \
  --single-ckpt-name stage2_interleave_18k \
  --single-ckpt-step 18000 \
  --tasks mmlu,kmmlu,kobest,click,csatqa,arc_easy,arc_challenge,hellaswag,openbookqa \
  --result-root sweep_results/stage2_interleave_18k_main \
  --cache_root ./hf_cache \
  --dtype bf16 \
  --device_map auto
```

## Korean Reranking Evaluation

`korean_rerank` expects a candidate JSONL file. The expected schema is described
in `docs/korean_rerank_benchmark.md`.

```bash
python eval_paper_benchmarks.py \
  --ckpt_path checkpoints/stage2_interleave_18k \
  --model_arch krong \
  --task korean_rerank \
  --rerank_data rerank_candidates/miracl_ko_hardneg.jsonl \
  --rerank_max_candidates 100 \
  --cache_root ./hf_cache \
  --out_json outputs/korean_rerank.json
```

## KoBEST Stress Evaluation

`kobest_variant` expects prebuilt stress JSONL files under `variant_benchmarks/`.
Those data files are not generated by this trimmed reviewer repository.

```bash
python eval_variant_hf_krong.py \
  --ckpt_path checkpoints/stage2_interleave_18k \
  --model_arch krong \
  --task kobest_variant \
  --variant_data_root variant_benchmarks/ko_random_p25 \
  --variant_name ko_random_p25 \
  --kobest_tasks boolq,copa,hellaswag,sentineg,wic \
  --kobest_split test \
  --k_shot 5 \
  --continuation_scoring oneshot \
  --cache_root ./hf_cache \
  --out_json outputs/ko_random_p25_predictions.json
```

## Training Reference

`training/stage2_train.py` is included for code inspection and artifact
completeness. It is not needed for evaluating the downloaded checkpoints.

## Verification

Run a syntax/import smoke check:

```bash
python -m compileall \
  eval_paper_benchmarks.py \
  eval_variant_hf_krong.py \
  run_eval_checkpoint_sweep.py \
  krong_eval \
  krong_eval_variants \
  training
```

Then run one small benchmark with `--limit 1` after dependencies and Hugging
Face access are configured.
